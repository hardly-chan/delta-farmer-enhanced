# Generalize the spread resizer to all supported exchanges

## Goal
Today `apps/spread.py` is hardwired to Omni + Pacifica. Generalize it to support **any two of the 8 supported exchanges** (`ethereal`, `hyena`, `hyperliquid`, `nado`, `omni`, `onyx`, `pacifica`, `rise`, `zero1`), picked positionally at the CLI:

```
uv run apps/spread.py status omni pacifica
uv run apps/spread.py run   omni pacifica --action reduce --amount 500
uv run apps/spread.py plan  hyena nado    --action increase --amount 1000
uv run apps/spread.py close omni pacifica
```

All 8 venues implement the `TradingClient` protocol with `exchange`, `from_config()`, `get_bbo()`, `positions()`, `market_order(..., reduce_only=)`, `get_price()`, `get_lot_size()` — verified. (`hyena`/`onyx` subclass `HyperLiquidClient`; the `hyperliquid` venue maps to `apps.hyperliquid.HyperLiquidNativeClient`.)

## Account selection: a `passive_farm` flag in existing per-venue configs

Per your idea: **no new config file**. Each venue's accounts continue to live in `configs/<venue>.toml`. A new optional account field `passive_farm` selects which accounts the spread tool may use. The tool loads `configs/<venue>.toml`, keeps only accounts with `passive_farm = true` (and `enabled = true`), and errors out clearly if none exist.

Example (`configs/omni.toml`):
```toml
[[accounts]]
name = "omni_main"
privkey = "enc:..."
proxy = "http://..."
passive_farm = true   # ← opts this account into the spread tool

[[accounts]]
name = "omni_dumper"
privkey = "enc:..."
# no passive_farm → ignored by spread.py, still used by `apps/omni.py trade`
```

This keeps a single source of truth per venue, reuses the existing encrypted-key flow (no new encrypt step), and the flag is invisible to `apps/<venue>.py trade` (it ignores unknown fields — Pydantic default).

## Changes

### 1. `lib/models.py` — add `passive_farm` field to `AccountConfig`
```python
class AccountConfig(BaseModel):
    name: str
    privkey: SecretStr = Field(repr=False)
    proxy: str | None = None
    enabled: bool = True
    passive_farm: bool = False   # ← NEW: opts in to apps/spread.py
```
No validator needed; default `False` is backward-compatible. Existing apps are unaffected (their `StrategyConfig`/`AccountConfig` validation ignores extra fields? — *verify*: `StrategyConfig` uses strict `model_validate`, but `passive_farm` will now be a known field, so it's consumed silently everywhere).

### 2. New `apps/spread_registry.py` — venue registry (tiny)
A single dict maps venue name → client class + default config path:
```python
from clients.ethereal import EtherealClient
from clients.hyena import HyenaClient
# ... etc
from clients.nado import NadoClient
from clients.omni import OmniClient
from clients.onyx import OnyxClient
from clients.pacifica import PacificaClient
from clients.rise import RiseClient
from clients.zero1 import ZeroOneClient
from apps.hyperliquid import HyperLiquidNativeClient

VENUE_REGISTRY: dict[str, tuple[type[TradingClient], str]] = {
    "ethereal":    (EtherealClient,    "configs/ethereal.toml"),
    "hyena":       (HyenaClient,       "configs/hyena.toml"),
    "hyperliquid": (HyperLiquidNativeClient, "configs/hyperliquid.toml"),
    "nado":        (NadoClient,        "configs/nado.toml"),
    "omni":        (OmniClient,        "configs/omni.toml"),
    "onyx":        (OnyxClient,        "configs/onyx.toml"),
    "pacifica":    (PacificaClient,    "configs/pacifica.toml"),
    "rise":        (RiseClient,        "configs/rise.toml"),
    "zero1":       (ZeroOneClient,     "configs/zero1.toml"),
}
KNOWN_VENUES = sorted(VENUE_REGISTRY)
```
Kept in its own module so `strategy/spread.py` (no app-layer deps) stays clean and the import surface is centralized.

### 3. `apps/spread.py` — rewrite the config/client layer, keep everything else
- Replace `build_clients(args)` (hardcoded Omni/Pacifica) with `build_clients(venue_a, venue_b, args)`:
  - Looks up each venue in `VENUE_REGISTRY`; raises `AppError` for unknown names with a "known venues: …" hint.
  - For each venue: load accounts from its config, filter to `enabled and passive_farm`, pick the first (or the one matching `--<venue>-account` if provided), error if none.
  - Instantiate `client_cls.from_config(acc)`. Returns `dict[Venue, TradingClient]`.
- Parser: two positional `venue_a`, `venue_b` on every subcommand (`status`/`run`/`plan`/`close`), validated against `KNOWN_VENUES` via `choices=KNOWN_VENUES` so argparse itself rejects bad names with a clean message.
- Drop the old `--omni-config`/`--pacifica-config`/`--omni-account`/`--pacifica-account` flags. Replace with:
  - `--config-<venue> PATH` is *not* added (one flag per venue is messy with 9 venues). Instead a single `--configs-dir` (default `configs/`) resolves `configs/<venue>.toml`. Keeps it simple.
  - Per-venue account override: `--account-<venue> NAME` is also messy. Simpler: a single optional `--accounts NAME_A,NAME_B` positional-paired flag, OR just "first passive_farm account" with no override. **Recommendation: no per-venue account override in v1** — if you run multiple passive_farm accounts per venue, pick the first; override can come later.
- Update command handlers (`cmd_status`, `cmd_run`, `cmd_plan`, `cmd_close`) to receive `args.venue_a` / `args.venue_b` and call `build_clients(args.venue_a, args.venue_b, args)`.
- Update docstring + `--help` examples to show generic two-venue usage.
- `strategy/spread.py` (the engine) needs **no changes** — it already operates on a generic `dict[Venue, TradingClient]`. The Omni/Pacifica-specific bits were only ever in `apps/spread.py`.

### 5. `readme.md` — add a short "Cross-exchange spread tool" subsection
Document the `passive_farm` flag, the venue list, and the 4 commands with two-venue examples. (Brief — matches the doc density of the rest of the README.)

## Defaults / decisions (flag any you want changed)
- **One account per venue.** First `passive_farm=true & enabled=true` account in each venue's config. No per-venue account override flag in v1.
- **Venue names are positional and strict.** `choices=KNOWN_VENUES` so typos fail at parse time.
- **No `--config-<venue>` overrides.** Single `--configs-dir` (default `configs/`) for simplicity.
- **`passive_farm` defaults to `False`**, so existing configs work unchanged; users opt in per account.
- **The Omni↔Pacifica assumption in the docstring/header** gets generalized to "any two venues".
